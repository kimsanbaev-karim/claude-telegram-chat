# /connect-telegram — канал с владельцем в Telegram

Открывает двусторонний канал между этой сессией и темой задачи в группе с темами. Одна задача — одна тема.

Канал держит отдельное трей-приложение (router поллит Telegram и раскладывает сообщения по лентам тем). Сессия только читает свою ленту и пишет ответы.

Дальше `ПАПКА_КАНАЛА` — каталог, куда склонирован этот репозиторий, `СОСТОЯНИЕ` — каталог состояния (`~/.claude-telegram-chat` либо путь из `AI_PAIR_STATE_DIR`), `ID_ГРУППЫ` — id вашей группы из `.env`.

## Аргументы

| Аргумент | Что значит |
|---|---|
| `<проект>#<задача>` | имя темы задано вызывающей стороной — бери его как есть, шаг 1 пропускается |
| `general` | режим General, см. ниже |
| `--then <скилл> <аргументы>` | канал открыт — вызови этот скилл инструментом `Skill` и дальше работай по нему |
| пусто | имя темы выясняешь сам по шагу 1 |

`--then` нужен потому, что харнесс разворачивает в первом промпте **только одну** slash-команду: всё, что идёт следом, приходит ей аргументом (замерено: промпт из двух команд пришёл как одна с чужой командой внутри `<command-args>`). Так внешняя панель открывает задачу одной кнопкой: `/connect-telegram <проект>#<задача> --then <скилл задачи> <id задачи>` — канал первым, задача вторым, иначе тему не к чему привязывать.

## Режим General — дежурный инстанс

Вызов `/connect-telegram general` подключает сессию не к теме задачи, а к **General** — общему потоку группы. Это дежурный инстанс: владелец пишет в General любую команду, и она приходит сюда.

Шаги 1 и 2 пропускаются, темы искать не нужно. Ключ ленты — слово `general`:

```
cd ПАПКА_КАНАЛА && .venv/Scripts/python.exe -X utf8 bind.py --general --session <id сессии>
echo "текст" | .venv/Scripts/python.exe -X utf8 reply.py
```

Ответы в General идут через `reply.py` **без** `--thread`.

**Сразу после наблюдателя прочитай, что осталось без ответа.** Инстанс поднимают ПО ФАКТУ сообщения, то есть команда пришла в ленту раньше, чем ты запустился, а `follow.py` печатает только новые строки — без этого шага первое сообщение потеряется.

Непрочитанное — это id из `СОСТОЯНИЕ/pending/general.json`; сами тексты лежат в `СОСТОЯНИЕ/inbox/general.jsonl` в строках с такими `message_id`. Пустой список — значит тебя подняли кнопкой, а не сообщением, и догонять нечего.

## Шаг 1 — определить имя темы

Имя темы всегда `проект#задача`. Одинаковые id задач в разных проектах иначе схлопнутся в одну тему.

Имя пришло аргументом — бери его и иди к шагу 2. Иначе спроси владельца одной строкой, к какой задаче подключаемся, и не выдумывай имя сам.

## Шаг 2 — найти тему или создать

Сначала **поиск** по списку тем группы `ID_ГРУППЫ`, затем точное совпадение по заголовку. Ботом список тем получить нельзя — в Bot API нет такого метода, — поэтому ищут личным аккаунтом (например, через telegram-MCP `list_topics`).

Нашлась — запомни id, ничего не создавая:

```
cd ПАПКА_КАНАЛА && .venv/Scripts/python.exe -X utf8 bind.py --name "проект#задача" --thread <id>
```

Не нашлась — создай тему ботом (id вернётся и запишется в реестр):

```
cd ПАПКА_КАНАЛА && .venv/Scripts/python.exe -X utf8 bind.py --name "проект#задача"
```

Реестр тем живёт в `СОСТОЯНИЕ/threads.json` и переживает перезапуски. Он нужен именно потому, что в Bot API нет метода получить список тем: бот узнаёт id ровно один раз — когда сам создал тему.

## Шаг 3 — поднять наблюдатель

Один вызов `Monitor`, `persistent: true`:

```
cd ПАПКА_КАНАЛА && while true; do .venv/Scripts/python.exe -X utf8 follow.py --thread <id>; echo "[канал] follow.py отвалился, переподключаюсь"; sleep 2; done
```

Цикл обязателен: `follow.py` может отвалиться — сеть моргнула, router перезапустился, — и без цикла канал молча умирает до конца хода. С циклом он поднимается сам через две секунды, а строка о падении приходит событием, так что обрыв виден.

Потолок Monitor в 30 минут циклом не лечится: по истечении подними наблюдатель заново, это отдельная механика харнесса.

Каждое сообщение приходит одной строкой `[ai-pair] текст`; у картинок добавляется `| файл: путь` — его можно сразу `Read`. Голосовые распознаются локально, в строку попадает уже текст.

Проверено замером: событие Monitor приходит **посреди** работающего инструмента, а не после хода. Поэтому канал и годится для парного режима.

## Шаг 4 — как отвечать

Текст идёт через stdin, не аргументом: argv на Windows приходит в ANSI и портит кириллицу.

```
echo "текст ответа" | .venv/Scripts/python.exe -X utf8 reply.py --thread <id>
```

Вложение — тем же скриптом, ровно одно на сообщение (два флага разом argparse не пропустит), текст со stdin становится подписью:

| Чем отдать | Флаг | Что увидит владелец |
|---|---|---|
| голос | `--voice ответ.ogg` | голосовое сообщение |
| картинка, скриншот | `--photo кадр.png` | фото в ленте, до 10 МБ |
| ролик, запись прохождения | `--video прогон.mp4` | видео с плеером, до 50 МБ |
| любой файл: лог, архив, отчёт | `--file отчёт.zip` | документ, до 50 МБ |

Лимиты — из Bot API (multipart-загрузка: 10 МБ фото, 50 МБ остальное). Скрипт проверяет размер ДО заливки и падает с подсказкой, чем пережать, — не жди отказа от Telegram через минуту.

Видео отдавай именно `--video`: `.mp4` голосовым (`--voice`) приходит файлом, который не открывается.

Отвечай коротко и только по делу: владелец читает телефон, а не терминал. Длинное объяснение оставляй в терминале, в телегу — итог и вопрос.

## Шаг 5 — сказать, что канал открыт

Одной строкой: какая тема, и что теперь можно писать прямо в неё. Дальше работай по задаче, а сообщения обрабатывай по мере поступления.

## Шаг 6 — продолжение, если пришёл `--then`

Вызови названный скилл инструментом `Skill` с его аргументами и дальше веди работу по нему — канал уже открыт и мешать не будет. Канал не поднялся (трей мёртв, группа недоступна) — продолжение всё равно выполняется: задача должна открыться, а про непойманный канал скажи одной строкой в терминале.

## Если канал молчит

Проверь по порядку:

1. Трей запущен? Процесс `tray.py`, иконка в трее. Если нет — запусти ярлык канала из автозагрузки.
2. Что в логе `ПАПКА_КАНАЛА/router.log` — там видно каждое принятое сообщение строкой `router: <тема> <- text #<id>`.
3. Дошло ли до ленты: `СОСТОЯНИЕ/inbox/<id>.jsonl`.

Сообщение есть в ленте, но не пришло событием — значит упал наблюдатель, подними Monitor заново.

## Чего не делать

- Не запускать второй router: `getUpdates` монопольный, второй поллер даст `Conflict` и канал замолчит у обоих. Router поднимает только трей.
- Не создавать тему, не поискав её сначала — иначе на каждую сессию появится дубль.
- Не отвечать в тему личным аккаунтом владельца: в теме должен писать бот, иначе владелец увидит собственные сообщения от себя же.
